Предварительное коммерческое предложение · 17 сентября 2026

Модуль поведенческого анализа клиентов и персональных уведомлений

Дополнительный модуль поверх действующей системы Cake Lab. Через открытый API выявляет устойчивые повторяющиеся покупки, фиксирует отклонение от привычного поведения и в согласованный момент формирует событие для персонального уведомления.

01Исходная ситуация

Что подтверждено по итогам встречи

В предложение включены только факты, зафиксированные на встрече. Неподтверждённые функции и гарантии не указаны.

01

У Cake Lab есть собственная система с открытым API.

02

В системе уже применяется базовая кластеризация клиентов — в том числе по частоте покупок и факту возврата.

03

Каналы обращений — приложение, сайт и Telegram-бот; обращения из всех каналов консолидируются в одной системе.

04

Значительная часть типовых заказов автоматизирована, сложные заявки обрабатывают сотрудники.

05

Рассматривается возможность более глубокого анализа индивидуального поведения клиентов.

02Решение

Дополни­тельный модуль поверх действующей системы

Система Cake Lab не изменяется: модуль читает данные через API и возвращает событие.

ШАГ 1

История покупок

Получение данных через API Cake Lab

ШАГ 2

Паттерны

Выявление устойчивых повторяющихся покупок

ШАГ 3

Отклонение

Фиксация расхождения с ожидаемым поведением

ШАГ 4

Событие

Формирование события для уведомления

ШАГ 5

Передача

В согласованный канал или ответственному сотруднику

Правила — в первую очередь

Базовые закономерности («каждый вторник», «раз в две недели») обрабатываются прозрачными алгоритмическими правилами. Их можно объяснить, проверить и настроить.

  • Порог устойчивости паттерна
  • Допустимое отклонение по времени
  • Момент срабатывания

Искусственный интеллект — по необходимости

Целесообразность применения ИИ для сложных отклонений определяется после обследования данных, а не заранее. Никаких обещаний «умной системы» до проверки на реальной истории.

  • Решение принимается по качеству и глубине данных
  • Сложные паттерны — отдельным этапом
  • В пилот включается только необходимое

Подтверждённый сценарий: регулярная покупка в определённый день

Клиент регулярно покупает определённый товар в определённый день недели. Когда устойчивая покупка пропущена, система фиксирует отклонение и формирует событие для персонального напоминания.

  2. Наступает ожидаемый день — покупки нет.
  3. Выдержано допустимое отклонение — фиксируется событие.

03Результат для бизнеса

Что получает Cake Lab

Коммерческий эффект и точность зависят от качества данных и правил сценария и оцениваются по итогам пилота.

01

Своевременное выявление изменений

Изменение привычного поведения клиента видно в момент, когда оно происходит, а не по итогам отчётного периода.

02

Персональный повторный контакт

Сообщение о конкретном товаре в конкретный момент — вместо массовой рассылки.

03

Снижение ручного анализа

Сокращение объёма ручной работы с клиентской базой.

04

Основа для программы удержания

База для последующих сценариев удержания клиентов.

04Принципы работы

На чём основано предложение

Документ построен так, чтобы каждое утверждение можно было проверить.

01

Только подтверждённые факты

В основе — пять фактов, зафиксированных на встрече. Неподтверждённые функции и гарантии не включены.

02

Риски названы до старта

Шесть рисков и десять открытых вопросов вынесены в отдельный раздел документа.

03

Стоимость и сроки — после обследования

Оценка даётся только после проверки данных. Это защищает обе стороны от необоснованных ожиданий.

04

Проверяемый результат

Пилот завершается техническим журналом срабатываний — итог подтверждается записями, а не презентацией.

05Обследование

Первый этап — обследование

Сроки и стоимость разработки не могут быть обоснованно названы до проверки данных и согласования правил.

06Пилот

Ограниченный пилот на одном сценарии

Окончательный состав определяется совместно с заказчиком по итогам обследования и настоящим документом не фиксируется.

ШАГ 1

Подключение к тестовому контуру API

Без доступа к рабочим данным и без изменений в действующей системе.

ШАГ 2

Обработка согласованного набора истории

Ограниченный, заранее согласованный срез исторических данных.

ШАГ 3

Один подтверждённый тип паттерна

Например, регулярная покупка в определённый день недели.

ШАГ 4

Фиксация отклонения и формирование события

По согласованным правилам выявления и срабатывания.

ШАГ 5

Технический журнал срабатываний

Результат пилота подтверждается записями журнала.

Критерии приёмки определяются на этапе обследования
07Риски и открытые вопросы

Что необходимо подтвердить до старта

Открытые пункты вынесены в документ, чтобы обсудить их на встрече, а не обнаружить в ходе проекта.

Риски, допущения, зависимости

  1. Состав и качество данных API не подтверждены.
  2. Канал уведомления и возможность автоматической отправки не согласованы.
  3. Не определены правила выявления устойчивого паттерна.
  4. Не подтверждены правовые основания и согласия клиентов на коммуникации.
  5. Инициатор и ответственный владелец проекта со стороны заказчика не установлен.
  6. Сроки, стоимость и показатели успешности определяются только после обследования.
